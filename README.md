# Field Agent

Android phone client (outdoor AR treasure hunt) for the **escape-game2** server. The phone is the
field half of a two-player date-night game: radar, AR chest, QR codes, photos, compass puzzles —
while Mission Control (the other player / game master) watches the trail and approves photos.

Package `dk.datestuff.hunt`, minSdk 28, Kotlin + Jetpack Compose, ARCore via SceneView.

## Pairing

1. Run the escape-game2 server and open Mission Control.
2. In the app, scan the pairing QR (`esc://pair?u=<url>&t=<token>`), or enter the server URL
   (e.g. `http://192.168.1.5:8667`) and token manually.
3. The app polls `/api/device/poll` (long-poll); when Mission Control starts a session you get the
   briefing, then the HUD with open field tasks, timer, inbox, codex and map.

While the hunt runs a foreground service reports the location (every ~10 s or 15 m), and the phone
vibrates when a target is under 50 m and on arrival.

## Step types

`gps-waypoint`, `geofence`, `ar-beacon`, `ar-chest`, `ar-collect`, `qr-scan`, `photo`, `selfie`,
`field-question`, `compass-bearing`, `tilt-lock`, `sprint`, `walkie` — see `SCHEMA.md` in escape-game2.
Steps with a waypoint show the radar until you are inside the radius.

AR steps need ARCore (`com.google.ar.core` is `optional`). Without ARCore the chest and collectibles
fall back to simple 2D versions; the beacon only needs camera + compass.

Offline: the last session is cached, solves/answers/photos are queued on disk and retried with backoff.
Answers are checked locally against the frozen campaign when the server is unreachable. Queued progress restores after restarting the app for that same mission. Uploads wait for the current connection to validate its session; pending records from previous missions are discarded.

## Building

```
./gradlew assembleDebug testDebugUnitTest lint
```

Needs JDK 21 and the Android SDK (platform `android-37.0`, build-tools 36). Put `sdk.dir=...` in
`local.properties`. 3D assets (`app/src/main/assets/models/*.glb`) are generated by
`python3 tools/gen_models.py` (already committed). The VT323 font is OFL licensed (`licenses/`).

### Signing

`app/build.gradle.kts` signs `release` when either `keystore.properties` (project root:
`storeFile`, `storePassword`, `keyAlias`, `keyPassword`) or the env vars `SIGNING_KEYSTORE_PATH`,
`SIGNING_STORE_PASSWORD`, `SIGNING_KEY_ALIAS`, `SIGNING_KEY_PASSWORD` are present; otherwise the
release build fails. The release workflow also refuses to publish without the signing secrets, and verifies the APK signature before uploading. `VERSION_CODE` / `VERSION_NAME` env vars set the version.

Create a keystore once:

```
keytool -genkeypair -v -keystore release.jks -alias fieldagent -keyalg RSA -keysize 4096 -validity 36500
base64 -w0 release.jks   # -> secret SIGNING_KEYSTORE_B64
```

Repo secrets: `SIGNING_KEYSTORE_B64`, `SIGNING_STORE_PASSWORD`, `SIGNING_KEY_ALIAS`, `SIGNING_KEY_PASSWORD`.
Back up the keystore and its passwords outside the repository. Keep the same keystore forever, otherwise updates will not install over older versions.

## Release

```
git tag v1.0.1 && git push origin v1.0.1
```

`.github/workflows/release.yml` builds the APK (version name from the tag, version code =
run number + 100), renames it `field-agent-vX.Y.Z.apk` and attaches it to a GitHub release.
`ci.yml` runs `assembleDebug` + unit tests on every push. Lint uses classic UAST through `gradle.properties` because the bundled FIR lint analyzer crashes with the current Kotlin/AGP combination; no lint checks are disabled.

## Install / update with Obtainium (private repo)

1. Create a GitHub fine-grained personal access token: only this repository, permission
   **Contents: read-only**.
2. Obtainium → Settings → add the token under "GitHub personal access token".
3. Add app → paste the repo URL (`https://github.com/icewall905/datestuff-hunt`).
4. Under the app's additional options set the APK filter regex to `field-agent-.*\.apk`.
